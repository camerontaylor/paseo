## Crash-point table

| Crash between | State on disk | What `activate()` recovery does |
| --- | --- | --- |
| admission → claim | item `pending` (attempts 0) | queued normally; delivered exactly once (identity + drainedIds) |
| claim → receipt write | item `dispatching`, attempts/attemptSeq already bumped; receipt file absent for this attempt | `queue` intent: prompt never sent (receipt pending is committed before any send) → resumes `pending` and delivers. `steer_strict`: admission may have reached the provider → held `uncertain` (`queue_claim_interrupted`) |
| receipt write → dispatch outcome | receipt `pending` | item held `uncertain` (`agent_request_outcome_unknown`); never auto-resent; `agent.queue.retry` is the only resend path |
| dispatch → removal | receipt `completed` | treated as delivered: item removed, id recorded in `drainedIds` so a late enqueue retry of the same id is a no-op |

Repeated reconnect cannot duplicate turns: enqueue is accept-once by item id
(including after delivery, via `drainedIds`), claims are atomic under the
per-agent store lock, and dispatch work is serialized on a per-agent tail.
After 8 known-failed attempts the item parks in the visible `failed` state
with `lastError`, resumable only by explicit retry/discard. Full narrative in
`docs/queue-mirroring.md`.

## Known gaps / deferred

1. **Daemon e2e not ported or run.** `agent-queue-mirroring.e2e.test.ts`
   parks a real `claude` provider agent on a Bash permission to make the
   queue observable; that needs real provider auth (`packages/server/.env.test`
   credentials) which this host does not have (no `~/.claude/.credentials.json`),
   and the repo forbids auth gates in tests. It also depends on
   DaemonClient queue helpers that do not exist in our client test-utils yet.
   Recommendation: port it in TM-03/P4 on a machine with provider creds, or
   re-anchor it on a fake-provider daemon harness if one is built.
2. Mixed-version coverage is split across layers rather than one test:
   parse-compat and capability gating in `messages.agent-queue.test.ts`
   (9 tests), legacy-path behavior in
   `session.test.ts > "a legacy send_agent_message_request never reaches the
   queue service"` (receipt-backed response shape asserted, queue untouched).
3. `send_now` may deliver a later item ahead of a still-pending head — an
   explicit, revision-checked user action; the response carries the
   post-attempt queue so the client sees the outcome. Flagged as a design
   call, not a gap.
4. A refused `steer_strict` item is retried on lifecycle wakeups; if none
   come, it delivers as a normal run when the turn ends (never interrupts,
   never deletes). Documented in `docs/queue-mirroring.md`.
5. Startup resume covers agents already loaded and idle at `activate()`;
   on-demand agents resume on their next running→idle transition. A queued
   prompt for an agent nobody opens after restart waits — deliberate, so the
   daemon never spawns providers just to drain queues.
6. `docs/queue-mirroring.md` added as the subject doc (the ported code's
   comments reference that path); CLAUDE.md docs table has the row.
