# WE REFERENCE AUTHOR FORK BRANCHES, NOT `upstream/pull/N/head`.

# `refs/pull/N/head` STOPS UPDATING the moment a PR closes. The author's fork
# branch does not. On 2026-09-07..09 the maintainer adopted a policy of
# auto-closing feature PRs (CONTRIBUTING.md, "This PR remains closed unless I
# explicitly follow up"), which closed eight lines of this basket in three days.
# A PR ref now means "frozen at the instant upstream slammed the door", and the
# rot becomes ours to pay.
#
# Measured 2026-09-10: seven of eight carried branches were still byte-identical
# to their frozen PR ref, because the closes were only days old. #2785 was not —
# colonelpanic8 rebased onto upstream/main of 09-09, the day AFTER the close, and
# added three commits: "adapt provider accounts to refreshed interfaces",
# "adapt provider account styles to current theme", "adapt provider account
# harness to current services". That is exactly the silently-rotting joint the
# fork README warns about, and the author is still paying for it. The frozen ref
# throws all three away.
#
# Each line's remote is configured in DESVIO_REPO with a SINGLE-BRANCH refspec,
# so `git fetch <author>` costs one branch and not a whole fork:
#   git remote add <author> https://github.com/<author>/<repo>.git
#   git config remote.<author>.fetch "+refs/heads/<br>:refs/remotes/<author>/<br>"
# Use braces. Bare `$br:refs/...` loses the `:r` to zsh's root-name modifier and
# writes a refspec with no colon in it; the fetch then fails with
# "couldn't find remote ref", which is not what a missing colon sounds like.
