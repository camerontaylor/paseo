## RALPLAN-DR

Principles: keep the five deployed refs frozen; adapt source behavior while preserving our stronger contracts; give each subject a declared removal boundary; stack only real dependencies; reuse maintained mechanisms.

Decision drivers: queue and Stream data integrity; bounded GLM stages with Opus checks; manageable assembly conflicts and traceable removal.

| Option                                 | Benefit                                                                       | Cost                                                              |
| -------------------------------------- | ----------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| Extend existing carries                | Few branches and simpler assembly                                             | Changes reviewed refs and combines old and new removal boundaries |
| Consolidate `mine` into `custom`       | One assembled development base                                                | Moves foreign features into core and loses the fork's separation  |
| Fresh per-source `-r2` carries         | Keeps frozen refs intact with fewer manifest lines                            | Couples unrelated additions; rollback needs commit selection      |
| Subject overlays with rolling assembly | Keeps frozen refs intact and gives each subject a reviewable removal boundary | More branches and repeated integration checks on shared files     |

Choose subject overlays. They preserve data-integrity reviews and bound worker scope. Rolling assembly exposes conflicts after each package; it does not eliminate integration cost. Per-source replacement carries remain a reasonable alternative if maintenance cost later exceeds the value of separate removal boundaries.

## 2. Guardrails (global; the shared preamble references these)

1. No production daemon contact: no restarts (port 6767), no config changes, no installs/publication. Timeouts ≠ restart signals.
2. Targeted tests only: `npx vitest run <file> --bail=1`; never full suites locally; broad verification via remote CI on basket candidates. **Never add auth checks to tests.** Lint/format via npm scripts only; typecheck+lint after every change.
3. Build the owning stack first in the worker's worktree (`npm run build:client`, plus `build:server` for server/CLI/protocol) before diagnosing cross-package type errors; never patch inferred params or duplicate types.
4. Protocol: new fields optional; never narrow/remove/require; pure wire schemas (no `.transform()`/`.catch()`/`.preprocess()`); discriminated unions; dotted RPC names with `.request`/`.response`; **existing question `kind`/`status` enums stay UNCHANGED — never add literals to them**; richer ask state lives only in a nested optional `ask` object; client→server additions (`set_ask`, `expectedRevision`) gate once on `server_info.features.<trackedAsks>`; **every server-pushed message type gated on a client capability** (client package's exhaustive defaults) — a features flag alone does not cover pushes; `// COMPAT(<name>)` tagged with **our** version; every push gets an old-client-parse test.
5. Persistence: stores own atomicity (temp+rename, 0600 where sensitive); no migrations; **server owns server-side state** — a client unsubscribe/disconnect/panel-close releases only that client's delivery, never server state (inhibition, wake deadlines, queue).
6. **Locale parity: all 9 locale resources**, enforced by the existing `packages/app/src/i18n/resources.test.ts` (extend it; no new scripts). infi's optional-TranslationResources weakening must not come across.
7. Platform rules apply to `packages/app` (+desktop shell) only: `isWeb`/`isNative`/`getIsElectron()`/compact-form-factor; Metro file splits over `if` ladders; no `onPointerEnter/Leave`. **Server/desktop-main code is plain Node**: platform dispatch via `process.platform`.
8. Transport/classifier (C6): no private ChatGPT Responses endpoint/token plumbing; no native agent/MCP/hook launches. Classification tools-off, bounded I/O, scoped validated candidates, selected credentials honored. Confirm the maintained configured-provider seam with file:line evidence; if none exists, a bounded new standard configured adapter is the declared prerequisite — never an unverified "existing transport" claim.
9. Views broadcast: explicit queue intent, stable agent IDs, no implicit interrupt, per-target partial results/failures. Queue preservation (C1): **8-attempt park + explicit retry/discard** (no source infinite retry); claim-in-place receipts; `uncertain`/`failed`; archived fence; no startup auto-dispatch; `durableAgentQueueV1`; legacy no-intent path; refusal never interrupts/deletes; one canonical row per drain.
10. **Quit authority (A2):** the upstream owned-launch capture (`ownedLaunch`, `readDaemonInstance`) is reused — but three interfaces (detection return, `confirmStopDaemon` signature, `stopDaemon` forwarding) are **explicitly adapted**, and no new reader or ownership store is built. A pre-existing `desktopManaged` daemon is prompted **only when `keepRunningAfterQuit=false`**, through a named confirm (home, PID, startedAt). For an unowned daemon the default button, the cancel button, the no-window fallback, a pre-prompt OS-signal abort, and a mid-dialog abort **all mean keep-running**. A quit-reason stop passes the prompt-time instance through the widened changed-since-confirmation recheck (`explicit` accepts `"manual_ipc"`/`"quit"`; `"quit"` additionally requires a matching `home`) and fails closed. A daemon with a null `startedAt` cannot be confirmed: it is never stopped, and that is logged. `app_update` and OS-signal quits never stop an unowned daemon. **The source `confirmedQuit` bypass is not taken**; quit IPC remains instance+home bound. Owned behavior is preserved at the level of **assertions and expected outcomes**: only the mechanical dep-signature adaptations declared in the [PF] s2 preflight are permitted, with **no boolean overload or adapter shim**. Tag `FORK(daemon-shutdown-confirmation)`; the manifest line carries the removal note.
11. **Stream retention:** persisting ALL captured history deliberately grows disk; read/payload bounds are a transport mitigation, not a disk one. `ENOSPC`/`EIO` surface as logged, user-visible degraded capture: never acknowledge a failed write, never evict to make room, never take the session down. Earlier pruned history is not recoverable (recorded limitation).
12. Sources: pinned SHAs only (§1); attribution `Source: <repo>@<sha>` in commit bodies; no version/branding churn; **source `docs/fork.md` hunks relocate to `fork/` or are dropped** (changes to upstream-owned docs need file:line justification); release-watch dirty files untouched; docs updated in-branch (fork-local notes in `fork/`).

## ADR

**Decision:** adopt the identified source work in subject overlays on frozen owners, with declared prerequisites, path-limited extraction, capability-gated wire delivery, and rolling integration after each package.

**Drivers:** durable message/history integrity; bounded implementation and review; explicit source provenance and removal dependencies.

**Alternatives:** extending carries simplifies assembly but changes frozen refs; per-source replacement carries preserve refs with fewer lines but couple features; consolidating into custom changes the core/foreign-feature boundary.

**Why chosen:** subject overlays keep each change reviewable by an Opus advisor while GLM implements bounded stages. Rolling integration checks the actual basket rather than assuming individual branch ancestry represents the deployment.

**Consequences:** more branches and conflict resolution, particularly in protocol/session/composer files. Existing reviews cover unchanged refs; new overlays and their assembled interactions need their own evidence. Conditional source or hardware gates remain visible.

**Follow-ups:** close source-pinning and package checks during implementation; record tested basket SHAs, technical gates and missing QA evidence. Manifest activation, releases and production repair are separate work.
